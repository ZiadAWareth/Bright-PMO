# Bright PMO (V2)

Project and portfolio management for construction and engineering work:
EPS, portfolios, projects, WBS and scheduling, resources, risks, budget,
procurement, documents, timesheets and approvals. V2 adds Agile (Scrum and
Kanban) and Hybrid projects alongside Waterfall, and multiple organisations.

## Repository layout

| Folder | What it is | Port |
|---|---|---|
| `PMO-Client/` | The frontend. Next.js 15, React 18, Tailwind v4. No server code. | 7060 |
| `PMO-Legacy-API/` | The old backend: Next.js API routes + Prisma on PostgreSQL. Kept running until every screen uses the new backend, then deleted. | 7061 |
| `PMO-Soul-Backend/` | The new backend: NestJS 11 + Prisma, generated by Soul from `docs/target-schema.prisma`. Runs locally on its own database; not yet used by the client. See its README. Soul also deploys an admin panel for the super admin (tenants, tenant admins, roles); its generated frontend is not used. | 7062 |
| `PMO-Soul-Admin-Panel/` | Soul's generated admin panel: platform administration (tenants, users, roles, workflows) against the new backend. See its README. | 7063 |
| `migration/` | Scripts that copy legacy data into the new backend's database. See its README. | |
| `docs/` | The target schema, conventions and integration notes. | |

The browser only talks to `PMO-Client`. It forwards API calls on its own origin
(`PMO-Client/next.config.ts`), so cookies and sign-in work the same for both
backends:

```
browser ──> PMO-Client :7060 ──/api/*─────> PMO-Legacy-API :7061
                              └─/backend/*─> PMO-Soul-Backend :7062   (once BACKEND_URL is set)
```

Screens move from `/api` to `/backend` one feature at a time. When nothing calls
`/api` any more, `PMO-Legacy-API` and its rewrite are removed.

## Running locally

Requirements: Node.js 20+ and access to the PostgreSQL database.

1. **Environment.** In each app folder, copy `.env.example` to `.env` and fill it
   in. The `JWT_*` values must be identical in both apps.
2. **Install** in each app folder: `npm install`.
   - npm 11 no longer runs packages' install scripts unless they are approved.
     The legacy API's own `postinstall` runs `prisma generate`, so its database
     client is created anyway. If PowerPoint/PDF generation complains that
     Chrome is missing, run `npx puppeteer browsers install chrome` there.
3. **Start the legacy API first**, then the client, in two terminals:

   ```
   cd PMO-Legacy-API && npm run dev     # http://localhost:7061
   cd PMO-Client     && npm run dev     # http://localhost:7060
   ```

   To use the Soul backend too, set it up once as described in
   `PMO-Soul-Backend/README.md` ("Running locally"), then start it in a third
   terminal: `cd PMO-Soul-Backend && npm run start:dev` (http://localhost:7062).

4. Open http://localhost:7060.

## Checks before committing

In each app you changed:

```
npm run typecheck     # must report 0 errors
npm run lint          # PMO-Client only; must report 0 errors
```
